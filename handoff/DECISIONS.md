- 2026-09-27 [repo] fork(): the brief's vfork semantics (parent suspended, child in the parent's space until execve) plus a copy-on-write snapshot: at fork every writable host page of the parent is write-protected and the VMA table/brk copied; the child's first write to a page (host fault → kernel hook, or a kernel write) saves the old contents, and when the child execs or exits the parent's pages, VMAs and brk are restored. Reason: dash/busybox children run builtins and touch shell state before exec; plain vfork would corrupt the parent. Nested forks push nested snapshots. CLONE_VFORK (posix_spawn) skips the snapshot.
- 2026-09-27 [repo] futex on host condition variables (one wait queue per word, prepare/notify generation counting) instead of os_sync_wait_on_address / __ulock: portable, unit-tested on Linux, correct for WAIT/WAKE/(CMP_)REQUEUE/WAKE_OP with bitsets and timeouts; switch to the OS primitive only if profiling shows the table lock.
- 2026-09-27 [repo] Guest signals are delivered at syscall boundaries only (frame built from FEXCore's CPUState at the end of the syscall; rt_sigreturn restores it). A thread executing JIT code sees a signal at its next syscall; blocked syscalls are interrupted (EINTR / SA_RESTART restart). Asynchronous delivery into JIT code (FEX's SRA spill + RestoreRIPFromHostPC + ReconstructCompactedEFLAGS, all exposed by FEXCore) is the C4/C5 item — needed for Wine's SIGUSR1 suspension and for turning guest faults into SEH.

- 2026-09-27 [repo] FEXCore's heap on Darwin is the system allocator (libmalloc), not FEX's rpmalloc (`ENABLE_FEX_ALLOCATOR` off on Apple; `AllocatorHooks.cpp`'s system branch gained Darwin spellings: posix_memalign for memalign/aligned_alloc, malloc_size). Evidence (result 003): rpmalloc 2.0 gives every host thread its own heap of 256 MB spans, each mapped as 512 MB with the alignment slack kept, 4 spans per heap, and nothing finalized a guest thread's heap — 2 GB of the TV's ~7.25 GB address-space budget per finished guest process, so the 4th guest of an app instance died in `IntrusivePooledAllocator::ClaimBufferImpl` on a NULL allocation. Finalizing heaps would only help sequential reuse: Wine's chain keeps tens of threads alive at once (≥ 1.5 GB each under rpmalloc). FEX uses rpmalloc to keep its heap apart from the guest's glibc; here the guest never sees the host heap, so libmalloc's shared zones are the right fit. Per-thread cost is now FEX's thread state + our 4 MB call-ret stack.

- 2026-09-27 [repo] Writable guest filesystem = an in-memory upper layer over the read-only rlvfs tree (overlay.h): tmpfs nodes consulted first at every path component, whiteouts, copy-up on write, opaque `/tmp` `/var/tmp` `/run` `/dev/shm` `/dev/pts` created at boot, merged listings.
