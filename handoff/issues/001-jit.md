# 001-jit — JIT on tvOS 27 / A15 (TXM): mechanism and plan

**Status:** open (REPO research + tooling done; LAPTOP to establish the
debugserver connection and run request 001 against build-4+).

## What is known (REPO, 2026-09-26, from public write-ups)

- Since iOS/tvOS 26 the Trusted Execution Monitor (TXM) enforces: a page an
  app has written code into does **not** execute — even with `get-task-allow`
  and a debugger attached — until **a debugger has written to that page**.
  Authorization is one debugger write per 16 KB page. After that the
  debugger may disconnect; the pages stay executable for the life of the
  process. It must be redone after every relaunch. tvOS has no on-device
  debugger (StikDebug is iOS-only), so the writes must come from the laptop.
  Sources: Provenance iCube issue "JIT is back on iOS 26"
  (https://github.com/Provenance-Emu/iCube/issues/11), StikDebug docs
  (https://github.com/StikDebug/StikDebug), SideStore JIT docs
  (https://docs.sidestore.io/docs/advanced/jit).
- Command-line route (gist "Enable JIT on iOS and tvOS from the command line",
  https://gist.github.com/tonycoco/66b08eea237ff64bf7becb54afb2e04d):
  `pymobiledevice3 mounter auto-mount`, then
  `pymobiledevice3 developer debugserver start-server`, then attach with
  lldb (`platform select remote-ios`, `process connect connect://[addr]:port`,
  `attach -p PID`, `continue`, `detach`). On iOS 26 the tunnel is
  `lockdown start-tunnel`. pymobiledevice3 documents a **no-root** option:
  add `--userspace` to any `developer` command and the iOS 17+ tunnel is
  built in-process over a pure-Python network stack (PyTCP) — no `sudo`, no
  TUN device (https://doronz88.github.io/pymobiledevice3/guides/ios17-tunnels/).
  A privileged `tunneld` is only needed for external tools (lldb) that must
  reach the RSD address themselves.

## What REPO built for it (build-4+)

- The app maps a fixed **JIT arena** at launch (`RLJitArenaMB`, 64 MB for
  the harness; RWX if `mmap` allows, else RW with mprotect toggling) and
  publishes it in `/status.jit_arena {base,size,prot,rwx_errno,pages}`. The
  startup JIT probe is map-only; nothing executes unauthorized pages.
- `tools/tv.py jit` (backend `gdbremote`) attaches to the app's pid through
  Apple's debugserver using a pure-Python gdb-remote client
  (`tools/gdbremote.py`: `vAttach`, `m`/`M` memory, `D` detach), writes
  every page of the arena back to itself, detaches, then runs
  `POST /run {"argv":["jittest","--trust"]}`; the app writes code into an
  arena page, executes it, rewrites it, executes again. `--madvise` and
  `--fresh` variants probe whether authorization survives `MADV_FREE` and
  whether fresh pages execute at all (expected: SIGKILL). A marker file
  makes a SIGKILL visible after relaunch (`/status.last_jit_kill`).
- Config (`laptop/config.env.example`): `DEBUGSERVER_ADDR=host:port` of a
  reachable debugserver/proxy, or `DEBUGSERVER_CMD` that starts one and
  prints its address (tv.py scrapes `connect://[host]:port` or a port), or
  `JIT_CMD` for an external tool, or an atvloadly MCP tool.

## What LAPTOP needs to establish (no sudo)

1. Pair the Apple TV with pymobiledevice3 (tvOS pairs over the network; the
   TV shows a PIN) and check `pymobiledevice3 lockdown info --udid <UDID>`.
2. Mount the developer disk image: `pymobiledevice3 mounter auto-mount
   --userspace --udid <UDID>` (tvOS 17+ personalized DDI; needs internet).
3. Start a debugserver reachable from the laptop without root:
   `pymobiledevice3 developer debugserver start-server --userspace --udid <UDID>`
   and note what address/port it prints. If only an RSD (IPv6) address is
   printed that is not reachable outside the process, look for a local
   port-forward option (`--local-port`/`developer debugserver` help) or use
   jkcoxson's `idevice` tools (userspace TCP stack) to expose a local port.
   Put the working recipe in `DEBUGSERVER_CMD`/`DEBUGSERVER_ADDR`.
4. Sanity: `python3 tools/gdbremote.py <host:port> probe` should print
   `qHostInfo`/`qProcessInfo` replies.
5. Then request 001: `tv.py launch --fresh && tv.py jit` — expect
   `authorized_pages` = arena pages and `jittest.ok = true`, and `JIT ok` on
   the TV.

## Open questions the run answers

- Does `mmap(PROT_READ|WRITE|EXEC)` succeed before any debugger attached
  (`/status.jit_arena.prot`, `rwx_errno`)? If not, does it after attach?
- Is authorization per virtual page and does it survive `MADV_FREE`?
- Memory cost: each authorized page becomes resident (64 MB arena → +64 MB
  `phys_footprint`); measure before/after with `tv.py mem`.
- Does `sigaltstack` work (`/status.sysinfo.sigaltstack`)?

If no debugger route to tvOS 27 can be made to work, the FEXCore JIT
skeleton is blocked: write the evidence here and stop for the user.
