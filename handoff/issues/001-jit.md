# 001-jit — JIT on tvOS 27 / A15 (TXM): app side (REPO)

**Status:** open. LAPTOP's `003-jit-txm-brk-protocol.md` defines the protocol
(StikDebug `universal.js`: `brk #0xf00d` stubs, debugger-prepared RX
region, RW alias via `vm_remap`); LAPTOP builds the debugger helper
(`laptop/jit.sh`), REPO builds the app side. This file tracks the app side.

## Agreed contract (from LAPTOP's issue, restated as REPO implements it)

1. Stubs in the main binary (`app/Sources/Native/jit26.c`, naked):
   `JIT26Detach`: `mov x16,#0; brk #0xf00d; ret`;
   `JIT26PrepareRegion(x0=addr|0, x1=len)`: `mov x16,#1; brk #0xf00d; ret`
   → x0 = prepared address (0 = failure). Legacy `brk #0x69` is not emitted.
2. Startup: map one RX pool (`PROT_READ|PROT_EXEC`, `MAP_ANON|MAP_PRIVATE`,
   `RLJitArenaMB`, default 128 MB), then on a background thread poll
   `P_TRACED` for up to `RL_JIT_WAIT_S` (60 s). `/status.jit.stage` shows
   `waiting-for-debugger`, `preparing`, `ready`, `failed`.
3. SIGTRAP guard: the crash handler recognises `brk #0xf00d` / `brk #0x69`
   at pc and returns with pc+4, x0=0 (no debugger → failure, not death).
4. `PrepareRegion(pool, len)`; on 0 → `PrepareRegion(0, len)` (debugger
   allocates). The returned RX range is the JIT pool.
5. `vm_remap` an RW alias of the pool (`VM_FLAGS_ANYWHERE`, then
   `vm_protect` RW). Writes go through the alias, `sys_icache_invalidate`
   on the RX side, execution at RX. `delta = rw - rx` is constant.
6. Self-test attached: write `mov x0,#42; ret` via RW, run at RX → 42; rewrite
   to 43, run → 43. `JIT26Detach()`; repeat with 44 → detached test. Both in
   `/status.jit` (`attached_test`, `detached_test`, `pool`, `rw_alias`,
   `wait_s`, `prepared_by` = `app-pool` | `debugger`). If the detached test
   fails the app logs it and keeps working attached.
7. FEXCore: code buffers are sub-allocated from the pool (executable
   `VirtualAlloc` requests go to the pool allocator through the
   `FEXCore::Allocator::mmap` hook); every write to code memory is rebased
   to the RW alias (`RLtvOS::ToRW(ptr)`); branch targets/entry points stay
   RX; the pool is never `munmap`/`mprotect`/`madvise`d; `brk` calls are
   serialised. x18 is never allocated (patched in `Arm64Emitter.cpp`).

## tv.py side

`tv.py jit` backend `cmd` runs `JIT_CMD` (LAPTOP's `laptop/jit.sh`; with
`JIT_LAUNCHES_APP=1` `tv.py cycle` lets it launch the app) and then runs
the in-app `jittest --trust`, which now means "report the pool self-test"
(the app has already executed; `--trust` is kept for compatibility). The
`gdbremote` backend (page-touch authorisation of an app RWX arena) stays as
an experiment but is not the plan for TXM devices.

## Build status

- build-8: RWX arena + page-touch flow (superseded; still reachable as
  `tv.py jit --legacy` / `/status.jit_probe`).
- build-11: `app/Sources/Native/jit26.c` implements items 1–6:
  naked stubs in the main binary (`nm` in the workflow checks
  `_JIT26PrepareRegion`/`_JIT26Detach`), background preparation at launch
  (P_TRACED wait, `RLJitWaitS` = 60 s), **debugger-allocated region by
  default** (`PrepareRegion(0, len)`); the in-place form (`PrepareRegion(pool,
  len)` on an app-mapped RX pool) is an opt-in experiment (`tv.py jitcfg
  jit_in_place=1`) because AetherPS4 found it "returns success, memory never
  executes" with StikDebug — the order in item 4 is therefore reversed
  (DECISIONS.md). `vm_remap` RW alias, self-tests 42/43 attached and 44/45
  after `JIT26Detach` (`jit_detach=0` keeps the debugger attached), SIGTRAP
  guard for unserviced `brk #0xf00d`/`#0x69` inside the stubs (pc+4, x0=0),
  first-fit pool sub-allocator (`rl_jit26_alloc/free/to_rw/to_rx`),
  marker file → `/status.last_jit_kill`, everything in `/status.jit`.
  Item 7 (FEX) is in `core/fex` + the vendored FEXCore: executable
  `VirtualAlloc` → `mmap` hook → pool (`RegisterDualMapping`), write-side
  cursor everywhere, `GetExecutableAddress` on escaping pointers (entry
  points, dispatcher pointers, ABI thunks, exit-function linker literal),
  `GetWritableAddress` for link/delink patches and atomic back-patches,
  icache maintenance on both aliases, `MAX_CODE_SIZE` 64 MB on Apple
  (pool 128 MB). `tv.py fex selftest` runs seven bare programs.

## Resolved 2026-09-27 (LAPTOP, result 001 re-run)

All open questions answered on the TV (`handoff/results/001-harness/verdict.md`,
issue 003 last section): the tvOS 27 Cryptex1 DDI from Xcode 27 (taken from
GitHub's `xcode-27` runner, `.github/workflows/laptop-tvos-ddi.yml`, installed
by `laptop/jit mount-ddi`) exposes debugproxy; `PrepareRegion(0, 128 MB)` is
serviced in 4.4 s (`prepared_by debugger`), `vm_remap` gives the RW alias,
execution keeps working after `JIT26Detach`, the in-place pool works as well,
and the pool costs +136 MB phys_footprint. FEXCore's JIT ran on build-15.
